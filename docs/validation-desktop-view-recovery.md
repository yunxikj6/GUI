# 重连后回到原来看的窗口位置

在“原始大小”下平移到一扇云端窗口，再点击“重新连接”，同一个查看器会恢复断开前的画面位置。实时连接中断后转到逐帧查看、从逐帧切回实时，也使用这个位置。云机分辨率或浏览器可用区域变化时，视窗会停在仍能显示的最近位置。选择“适应窗口”仍显示全桌面。

## 已有 InstaBox 桌面

Linux Chromium 的视口为 390 × 470 CSS 像素，已有云桌面为 823 × 512 像素。在默认观看状态下选择原始大小，把视窗左上角移至云桌面的 (93, 39)，然后点“重新连接”。两版都确认新的 WebSocket 已收到实际桌面矩形，且浏览器已重新绘制画面。

| 在同一页重新连接 | 断开前位置 | 重新绘制后位置 |
| --- | ---: | ---: |
| 原版本 | (93, 39) | (0, 0) |
| 修复后 | (93, 39) | (93, 39) |

云机控制归属保持不变，观看过程中未发送远端键鼠、分辨率或剪贴板指令。测试只记录观看端的位置、连接和绘制计数。[实机与隔离回归数据](measurements/desktop-view-recovery.json)

## 网络中断与尺寸变化

在 320 像素宽的 Chromium 中，用带四角颜色标记的私有 RFB 桌面分别覆盖手动重连、主动切换模式和切断 TCP 连接。观看、接管后本地平移、云桌面从 1280 × 800 变为 1024 × 640 均纳入对照。12 组场景含 20 次查看器画面替换。旧版 20 次都回到了左上角。修复后 20 次都回到原偏移，或在新画面边界处停止。

例如，接管后视窗原先在右下角 (960, 426)，改用分辨率较小的逐帧画面后停在 (704, 277)。切回较大的实时画面时继续从 (704, 277) 显示。另行验证了在重连期间失去控制权的情形：画面位置恢复后进入观看状态，本机点击或按键不会进入原应用。[Chromium 恢复回归](../tests/test_desktop_view_recovery_ui.py)

## 建立实时连接的耗时

另取三个全新的 Chromium 进程连接运行中的同一台 InstaBox。浏览器创建 WebSocket 到首次把解码后的远端矩形画到可见画布，分别耗时 965、1013、1049 毫秒。这三次测量适用于该 Linux 客户端及当时的网络条件，仅覆盖建立实时连接后的首帧，不含云机唤醒，也没有测量应用菜单响应。[原始时间点](measurements/desktop-view-recovery.json)

## 回归

本机从独立源码快照运行 173 项回归，全部通过，零跳过。其中 72 项使用 Chromium，9 项使用原生模型 CLI。耗时 295.740 秒。[测试清单](measurements/regression-desktop-view-recovery.txt)
