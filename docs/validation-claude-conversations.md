# Claude Code 续聊与升级验收

从工作台选择「Claude Code · 只读」并发送问题。在成功回合打开「继续此对话」提交追问，可通过「上一轮」和「下一轮」回看。每项任务使用工作台自己的 ID，原生会话 UUID 只在云机上使用。选择另一个编码工具来起草新任务时，已打开回合的追问仍交给原来的 CLI。

Linux 独立源码快照的 78 项回归全部通过，耗时 119.965 秒，零跳过。包括 21 项 Chromium 回归和 9 项原生 CLI 回归。[完整测试清单](measurements/regression-claude-conversations.txt)

## 浏览器连到 InstaBox

本机 Chromium 通过工作台启动器连接 InstaBox 的临时 Git 项目。云机运行已安装的 Claude Code 2.1.288。该测试为 CLI 使用独立的用户配置和仅监听云机回环地址的 Anthropic Messages 测试服务。模型服务按测试脚本返回文本或工具调用指令。此次核查时，云机的 Claude Code 和 Codex 均显示未登录。在线模型认证的历史记录见[此前的实机验收](validation-reviewed-edits.md)。

| 操作 | 实测结果 |
| --- | --- |
| 在首轮提问并等待输出 | 浏览器显示第一条回答。模型服务收到 1 次请求，首问出现 1 次。 |
| 将新任务的提供方切到 Codex，从已有 Claude 回合发送追问 | 请求仍交给 Claude。第二次模型请求中，首问、首答、追问各出现 1 次。模型收到的工具在两轮均为 `Glob`、`Grep`、`Read`。 |
| 丢弃服务端已接受追问的回执，刷新后在页面上重试 | 两次提交返回同一个子任务 ID。云机只产生 2 条任务记录、2 次模型请求。 |
| 查看上一轮和下一轮，再刷新 | 浏览器能分别读到两条原回复，刷新后仍选中子回合，任务显示成功。 |

另一组端到端实测让回环服务在追问时要求 CLI 执行一次 `Read`。在临时项目写入一段标记后，云机收到 3 次模型请求。标记只出现在第 3 次请求对应的成功 `tool_result` 中。Chromium 丢弃追问回执并重试，同一子任务在刷新后仍只有一条 Read 进度。工作台的工具状态行只显示工具名和动作，未附带读取路径或文件内容。[可复跑的原生回归](../tests/test_native_claude.py)

## 哪些会话可以继续

首轮使用服务端生成的 UUID 启动。Claude 的初始化事件及成功结果都确认该 ID 后，工作台才记录可恢复会话。后续使用同一工作区、同一提供方、指定父回合的 ID 找回原生会话。数据库写入在同一事务内校验请求身份及父回合，两个标签页竞争时只有一个新请求可以占用下一轮。

- Chromium 回归从两个标签页向同一回合发送不同追问，获准一方刷新重试后仍能取回同一条回答。另一方看见已有的下一轮，并保留自己输入的草稿。读文件时，状态行在 CLI 返回回答前可见，刷新后保留一条。[浏览器用例](../tests/test_claude_ui.py)
- 真实 CLI 恢复缺失 UUID 时，在发出模型请求前报告失败。工作台测试还覆盖 CLI 未确认恢复、返回其他会话标识、老版本不支持安全模式等情况。用户能从任务记录看到原因，并保留此前成功回合的输出。[原生协议用例](../tests/test_native_claude.py) · [任务回归](../tests/test_tasks.py)
- 使用上一版 `ff975a0` 和新版启动器在同一本机数据库轮换读写。测试以独立 CLI 替身控制任务时序。升级前已运行的 Codex 能自然结束并继续追问。早期 Claude 临时会话可以回读，旧启动器仍按原行为展示单轮记录。12 个交错重试只执行预期的两个追问，另有 8 个请求同时竞争一个 Claude 父回合，只创建了一个后继。两个不同项目中相同的目录名也能正确区分。[回合与数据库实现](../cloud/tasks.py)

## 工具与主机策略

在真实 CLI 的临时用户配置和项目中安装了会写入标记文件的钩子及本地插件，先用旧调用方式确认三类钩子都会触发。改用工作台后，新对话和续聊均未产生标记，配置的用户 MCP 服务也未启动。回环模型服务核验了用户配置中的合成密钥，收到配置指定的模型名称。仅支持旧选项的 CLI 会在工作台提示升级。[工具隔离用例](../tests/test_claude_isolation.py)

Claude Code 的安全模式保留主机管理员强制设置的策略。使用隔离挂载的 Linux 管理配置验证时，受管钩子仍会执行。工作台「只读」限制模型可调用的工具，部署者需自行管理云机的系统策略。

云机还从相同的源码快照运行了 44 项专项回归，其中 42 项通过。两项 Codex 系统配置模拟依赖 Bubblewrap，该实例缺少此工具，因此跳过。

## 复现

使用 Python 3.10+、Git、Chromium、Python Playwright 和安装在 PATH 中的 Claude Code、Codex。开发机还安装了 Bubblewrap 以测试 Codex 的系统级配置。各组测试使用临时工作区。原生 CLI 的成功协议路径可用合成凭据和本机回环服务重复验证。

```sh
python3 -m unittest discover -s tests -v
```
