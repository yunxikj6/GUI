# 关联工作树、差异与项目检查

用 `git worktree add` 创建的工作目录与主仓库共享对象和分支引用，但有自己的 HEAD、索引和工作文件。上一版工作台只把根目录内的 `.git` 目录识别为仓库。关联工作树使用的是一个指向 Git 管理目录的 `.git` 文件，因而即使已经编辑文件，侧栏也会显示“未获取分支”，差异视图显示“当前工作区没有 Git 差异”。

现在可以把任意已登记的工作树根目录作为启动器的项目打开。侧栏显示其分支或分离 HEAD 的短提交号，差异视图读取这份工作树相对 HEAD 的改动。项目检查分别检查它的工作文件和暂存区。该视图的合并比较仍有一个已知边界：若暂存改动后单独把工作文件恢复到 HEAD，两个方向的改动会抵消。[下一轮复现](../AGENTS.md)

## 同一台 InstaBox 上的旧版与新版

本机 Chromium 通过标准 HTTP 启动器连接同一份云机 Git 项目。工作树路径中包含中文和空格。主工作树保留一处带尾随空格的改动，关联工作树有一个已暂存文件、一个未暂存文件和一个未跟踪文件。

| 从浏览器进行的操作 | 观察结果 |
| --- | --- |
| 用上一版 `17f50f12` 打开关联工作树 | 文件预览能读到新内容，分支为空，差异视图却显示没有改动。选择主仓内一个普通子目录再运行检查，检查因所选目录外的尾随空格而失败。 |
| 用新版打开同一关联工作树 | 分支为 `review-cloud`，视图包含关联工作树的三种改动。打开主工作树显示 `main`，只出现主工作树自己的改动。 |
| 在关联工作树运行项目检查 | 首次成功。随后只在其暂存区放入尾随空格，再次检查明确报告工作区通过、暂存区未通过。刷新后仍能读取同一任务的失败原因。 |
| 将关联工作树切换到分离 HEAD | 侧栏显示与原生 Git 一致的短提交号，仍能查看该工作树的改动。 |
| 选择普通子目录或损坏的 Git 工作树 | 可预览文件，检查按钮显示不可用原因。损坏登记时，未保存的中文草稿在刷新和切换差异视图后仍可编辑。 |
| 打开仓库后从外部损坏、再修复登记 | 仅重新打开差异，分支与检查按钮即可反映新状态。恢复成干净仓库后，工作台正确显示空差异，同时保留草稿。 |

正常读取差异没有额外的状态请求。已知的 Git 问题消失或读取出现仓库错误时，界面才重新核对 Git 状态。回执到达前若已离开差异视图，当前编辑器和草稿保持可用。[浏览器回归](../tests/test_worktree_ui.py)

在本机另外交叉连接两代工作进程。旧网页连接新工作进程时，能显示关联工作树的分支和改动。新网页连接旧工作进程时，仍能确认普通主仓的空差异。两种组合均从浏览器完成了项目检查。

## 仓库范围与 Git 版本

文件服务和任务执行器共用同一个 Git 程序和仓库识别函数。所选目录本身没有 Git 登记时，项目检查不会向上搜索父仓库。关联工作树通过 Git 的管理目录、返回所选工作树的登记路径及共用目录三者核对。工作树移动并经原生 Git 更新登记后可继续使用。直接移动导致登记失效时，界面提示使用 `git worktree repair` 修复。没有注册为关联工作树的 `--separate-git-dir` 布局会显示支持范围，文件预览和编辑仍可用。[文件服务](../cloud/workspace.py) · [任务执行器](../cloud/tasks.py)

本机分别使用 Git 2.47.3 和 2.56.1 创建仓库，并以原生 Git 为对照。两种版本创建的普通关联工作树、裸仓库派生工作树，在创建、原生移动和修复后均返回正确分支与完整差异。从一个关联工作树再创建的 detached 工作树也使用独立索引。尚无首个提交的分支能显示已暂存的新文件；引用指向缺失提交对象时会显示读取错误。[工作进程回归](../tests/test_git_worktrees.py) · [版本对照](measurements/git-worktrees.json)

Git 2.56.1 支持 `git worktree add --relative-paths`。将运行器 PATH 收窄后，状态、差异和任务仍使用同一个选定的 Git 读取这类工作树。在另一项实测中，把由 2.56.1 正式创建的相对登记仓库移到运行 Git 2.47.3 的 InstaBox。浏览器提示“当前系统 Git 不支持此仓库格式，请升级云服务器上的 Git”，同时可以读取 README。将启动器的 `CLOUD_WORKSPACE_GIT` 明确设为无效的云端路径时，界面改为提示检查该路径。[启动器传输回归](../tests/test_bridge.py)

## 复核

本机从独立源码快照运行 125 项回归，全部通过，零跳过。其中 44 项使用 Chromium，9 项使用原生模型 CLI。耗时 184.663 秒。[测试清单](measurements/regression-git-worktrees.txt)

InstaBox 的专项回归共 76 项，73 项通过。该实例上的 Git 2.47.3 无法创建相对登记工作树，这一创建用例跳过，另有两项 Codex 测试需要实例未安装的 Bubblewrap。上述浏览器实测另行验证了旧 Git 打开新格式时的实际行为。[云机用例及跳过原因](measurements/git-worktrees.json)

```sh
python3 -m unittest discover -s tests -p 'test_git_worktrees.py' -v
python3 -m unittest discover -s tests -p 'test_worktree_ui.py' -v
python3 -m unittest discover -s tests -v
```
