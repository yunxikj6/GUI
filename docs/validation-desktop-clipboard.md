# 在实时桌面双向传递剪贴板文字

打开 Linux 桌面，点击“接管输入”，再打开“剪贴板”。把文字粘到“发送到云端的文本”，点击“发送到云端”，再到云端应用粘贴。支持扩展剪贴板的对端会在需要时索取正文。反方向先在云端应用中复制，核对“最近收到的云端文本”，再点击“复制到本机”。这两个按钮分别由用户决定何时改写另一端的剪贴板。[使用说明](../README.md)

## 在真实 InstaBox 显示上复核

本机 Chromium 打开工作台的正式桌面页面，通过随包的 noVNC 连接云机上的私有 TigerVNC 显示。云机在该显示上运行独立 GTK 进程，提供和读取测试文本。实验用本机夹具控制“观看、接管、交还”状态，用官方 exec 在本机回环 WebSocket 和云机权限为 0600 的 RFB Unix 套接字之间交换数据。原登录桌面及其剪贴板与实验隔离。[云机结果与页面资源摘要](measurements/desktop-clipboard.json)

| 在正式页面上操作 | 独立读取的结果 |
| --- | --- |
| 从云端取出文字 | 页面收到“云端文本，雪✓”时，本机系统剪贴板仍保存预置文字。点击“复制到本机”后，独立进程读到“云端文本，雪✓”。 |
| 向云端提供文字 | 用系统粘贴将“本机主动发送，月✓”放入发送框时，云端仍保存原文。点击“发送到云端”后，云机 GTK 进程逐字读到新文字。 |
| 浏览器拒绝写入本机剪贴板 | 页面选中完整返回文字，并提示使用系统复制命令。本机剪贴板保留原值。 |
| 交还输入并再次接管，或重新连接 | 交还后收发两栏清空，重新连接后未发送的文字也清空。 |

另在同一类隔离云机显示中，用鼠标把焦点交给实时桌面，在 GTK 输入框键入 `GTK`。从本机提供“起雪✓尾”后，在该应用按 Ctrl+V，控件实际内容为“GTK起雪✓尾”。再用 Shift 和方向键选中“雪✓”并按 Ctrl+C。查看器收到这两个字符时，本机系统剪贴板仍是“起雪✓尾”。点击“复制到本机”后，独立本机进程读到“雪✓”。[云机应用控件、选区与本机剪贴板记录](measurements/desktop-clipboard.json)

## 字符与会话边界

支持扩展剪贴板的 RFB 连接可以交付 UTF-8 文本。对于经典 RFB，浏览器回归验证了含重音字母和换行的 `café` 文本能完整往返。遇到中文或 emoji 时，页面保留发送框原文，提示该连接只支持 Latin-1。测试对端收到 0 条消息。已声明扩展通知但尚未确认正文交付能力时，页面提示稍后重试。[实时桌面浏览器回归](../tests/test_desktop_clipboard_ui.py)

同一组 Chromium 回归覆盖了 320 CSS 像素宽度、观看时收到的消息、交还输入后迟到的复制回执，以及逐帧模式和重连时的收发栏清理。

## 用同一个 GTK 输入框做对照

在本机 GTK 3.24.49 上，每条路径均独立运行三次。输入 `Probe42` 后按 Ctrl+A，四条路径的 GTK 选区均为 `[0, 7]`，本应用内复制再粘贴均得到 `Probe42Probe42`。另启 GTK 进程分别读取剪贴板（CLIPBOARD）和主选区（PRIMARY），随后由该进程提供“中文✓”，再从原应用粘贴。[逐路径记录](measurements/desktop-clipboard.json)

| 控制路径 | 第二个进程读取的文字 | 原输入框再次粘贴的文字 |
| --- | --- | --- |
| 原生 X11 | 两个选区均为 `Probe42` | 中文✓ |
| 工作台逐帧查看器 | 两个选区均为 `Probe42` | 中文✓ |
| GTK 3 Broadway | 两个选区均为空 | `Probe42`，第二个进程能回读自己提供的“中文✓” |
| TigerVNC 1.15.0 与 noVNC 1.7.0 | 两个选区均为 `Probe42` | 中文✓ |

TigerVNC 对照另外记录了 RFB 3.8 客户端收到的剪贴板事件，以及客户端提供 ASCII 和中英文后 GTK 实际读到的文字。正式页面实验另行验证了本机系统剪贴板写入。这组对照使用 ASCII 核对选区，使用中文和符号核对粘贴。公网交互延迟和拼音候选窗尚待单独测量。
