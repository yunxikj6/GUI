# 长任务输出与实时回放验收

打开长任务会先显示最新输出。点“较早输出”可以一直读到开头，“较新输出”沿记录顺序向后阅读。任务继续运行时，向上滚动阅读或选中文字会保留当前内容。用“回到最新输出”可以重新跟随任务。历史窗口的边界按标签页、工作区和任务保存，同一标签页刷新后可以继续阅读。

Linux 独立源码快照的 101 项回归全部通过，耗时 123.633 秒，零跳过。包括 34 项 Chromium 回归和 9 项原生 CLI 回归。[完整测试清单](measurements/regression-output-windows.txt)

## 从旧工作进程接回正在运行的任务

本机 Chromium 通过本机启动器连接 InstaBox 的临时 Git 项目。上一版 `e943eda8` 的工作进程实际启动任务、接收 CLI 输出并提交到 SQLite。验收用隔离的 CLI 替身控制输出内容和完成时间。

| 操作 | 实测结果 |
| --- | --- |
| 保持任务运行，先产生 560 条独立输出 | 旧网页从头读取 3 个非空事件响应，JSON 正文合计 606,966 字节。读到末尾后，滚回顶部只能看到第 161 条。 |
| 在同一数据库上升级并打开同一任务 | 新网页用 1 个末段响应看到第 560 条，JSON 正文 65,893 字节。沿“较早输出”读取共 10 窗，按顺序拼接与全部 560 条一致。 |
| 翻页时中断一次连接，用原边界重试 | 当前文字保留。重试成功后能读到更早记录，在最早窗口刷新能回到同一段。 |
| 阅读最早窗口时放行任务 | 任务又产生了 20 条输出并成功结束。页面状态更新，当前窗口文字保持一致。点“回到最新输出”能读到第 580 条。 |

另一次实测暂扣了云机已返回的“正在运行”末段。后台轮询先收到“已完成”，再放行旧回执。工作台补回了最后一条输出，状态保持“已完成”，第 580 条只显示一次。

本机 Chromium 还用真实鼠标滚轮向上滚动并选择一句文字。在新的输出到达和任务终结后，浏览器选区、所选文字的可视位置都得到保留。在 320 和 360 CSS 像素宽的视口可以点按翻页。窄屏打开工作台时，即使先进入文件面板并在后台收到末段，切回任务面板也会显示末条。对于连续 delta，96 段文本共 397,440 个字符，按窗口重新拼接后与原文逐字一致。[正常入口与故障回归](../tests/test_output_ui.py)

## 为旧记录保留两种游标

旧工作进程仍可用 `after` 从已确认位置向后读。新版在同一 `events` 接口提供 `tail: true` 和 `before`。窗口内事件按时间升序返回，每窗最多 160 个事件，事件数组不超过 64 KiB，连同任务信息的完整响应上限为 256 KiB。查询先利用 SQLite 的任务 ID 与事件序号索引定位，再按需取正文。

部分早期版本把一大段输出存在一条 SQLite 记录里。旧整行游标表示已消费整条记录，分块游标能指向记录中间。用取自实际事件的游标翻阅可以保留原来的换行、CRLF、汉字、表情及转义字符。测试覆盖两类游标指向同一物理位置、窗口内侧边界、并发插入，以及末窗游标交给原 `after` 继续补读的情况。[服务端实现](../cloud/tasks.py) · [游标回归](../tests/test_output_pages.py)

混合数据黑盒试验将 774 条物理记录拆成 835 个可见事件。浏览器向前、向后各读 25 窗，每次拼接后的 524,668 个字符均与原文一致。另在恰好 160 条短记录之前放入一条 14 MiB 的旧记录。初版窗口为判断还有没有前文，会取出这条旧记录，进程峰值为 45,568 KiB。现在查索引即可判断，同一响应仍为 8,294 字节，峰值为 15,076–15,084 KiB。真正翻入这条旧记录时，云端仍需载入该行原文，额外保存的分块位置最多为 161 个。

新网页连接旧工作进程时会沿用顺序补读，并在早期内容超出显示上限时提示兼容模式。旧网页连到新工作进程也可按原接口读至末尾。用一项 901 条物理记录的任务实测时，两种跨版本组合均能读完、切换任务，并在刷新后读到正在运行的 Git 检查结果。新版界面随既有静态脚本加载，运行中的旧启动器也能提供它。

云机还运行了 54 项专项回归，52 项通过，2 项需要 Bubblewrap 的 Codex 系统配置测试在该实例上跳过。

## 首次看到末条输出的开销

使用临时项目、同一组 8,000 条固定中英文输出和同一台 Linux 开发机。每个版本运行 3 次，各使用新的 Chromium 浏览器上下文。从打开页面开始计时，到最后一条已渲染为止，同时检查末条在视口内。响应字节只统计浏览器收到的事件接口 JSON 正文。[测量脚本](../experiments/log_open.py) · [逐次样本](measurements/output-open.json)

| 版本 | 看到末条的中位数 | 事件请求 | 事件 JSON 正文 |
| --- | ---: | ---: | ---: |
| 上一版 `e943eda8` | 11.106 秒 | 6 次 | 1,416,550 B |
| 输出窗口 | 0.437 秒 | 1 次 | 30,064 B |

两版各 3 次的请求次数与响应字节均一致。计时包含本机启动器请求和浏览器渲染，受共享机器的负载影响。连接 InstaBox 的实测另见上表。

```sh
python3 experiments/log_open.py --rows 8000 --samples 3
python3 experiments/log_open.py --source /path/to/previous-checkout --rows 8000 --samples 3
python3 -m unittest discover -s tests -v
```
