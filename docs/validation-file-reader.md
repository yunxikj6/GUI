# 从只读预览读到文件末行

在左侧文件树选择文本文件，超过 800 行时，预览顶部会显示“上一页”、行号范围和“下一页”。聚焦页码选择器后，Home 和 End 可以跳到首页、末页。在支持的 128 KiB 以内，所有行都来自打开时收到的同一份正文。需要修改文件时，点击“编辑文件”会打开完整正文。[使用说明](../README.md)

## 在 InstaBox 比较旧版和新版

使用一份临时 Git 仓库，通过本机启动器、Chromium 和云机文件服务打开四个文件，窗口设为 320 × 740 CSS 像素。对每个文件分别读取最后一行，另在新版逐页核对行号和内容。旧版提交为 `d78dbc0`。[云机原始数据](measurements/file-reader.json)

| 云机源文件 | 旧版只读预览 | 新版只读预览 |
| --- | --- | --- |
| 3,200 行，末尾没有 LF | 可读到末行 | 4 页，可读到末行 |
| 3,200 行，末尾有 LF | 可读到末行，误报长度限制 | 4 页，可读到末行，无截断提示 |
| 5,000 行，末尾没有 LF | 只能读到第 3,200 行 | 7 页，可读到第 5,000 行 |
| 5,000 行，末尾有 LF | 只能读到第 3,200 行 | 7 页，可读到第 5,000 行 |

四份文件合计核对了 16,400 行。每个文件只发送一次文件读取请求。只读翻页期间没有保存请求，也没有产生草稿。末尾的换行符结束当前行。连续两个换行符之间的空行会得到自己的行号。空文件显示“空文件”。

## 支持范围和编辑

本机用两种恰好 128 KiB 的文件验证边界。全部由 LF 组成的文件包含 131,072 个空行，分 164 页，页内最多渲染 800 行。只有一行的 128 KiB 文本可通过横向滚动看到最后的标记。CRLF、单独 CR 和 LF 都能作为行尾。超过文本大小上限时，文件服务会返回具体原因。[浏览器回归](../tests/test_file_reader_ui.py)

在 InstaBox 上另外打开含三种行尾的 131,072 字节文件。第 5 页选中第 3,518 行的一段文字，后台确认版本相同时，页码、选区、滚动位置都保留。从编辑器只改变末尾一个字节后，云机磁盘文件的 SHA-256 与预期字节串一致。再次打开缓存文件时，从云机改写第 7 页的末字节，再放行校验回包。第 5 页的选区和位置仍保留，跳到末页可见新内容。131,073 字节的文件在正常入口显示 128 KiB 上限。[云机回执及文件摘要](measurements/file-reader.json)

同一页内，通过鼠标拖选跨过空行的文字并按 Ctrl+C，Chromium 剪贴板中的 28 个字符与规范化行尾后的源正文完全一致，包括制表符、行首和行末空格。本机回归另覆盖连续两个空行。[原生复制回归](../tests/test_file_copy_ui.py)
