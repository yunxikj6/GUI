# 任务取消与只读问答验收

在独立源码快照上，Linux 全量回归 68 项全部通过，耗时 78.790 秒，零跳过。其中 19 项运行 Chromium，5 项使用原生 Codex CLI。[完整测试输出](measurements/regression-task-cancellation.txt)

## 取消的可见结果

在任务记录中选择一项可取消的任务，点击“取消任务”。云机将请求写入 SQLite 后，状态变为“正在取消”。回收任务进程及其派生的本机进程后，状态变为“已取消”。刷新页面或换一台客户端都能读取同一份结果及先前已持久化的输出。若任务已经完成，取消请求返回已存在的终态。

| 验收条件 | 已观察到的结果 |
| --- | --- |
| 排队期间取消 | 任务记录保留，模型 CLI 未启动。 |
| 输出中途取消 | 使用真实 Codex CLI 与回环模型服务，让首轮响应保持打开。在工作台已有部分输出时取消，CLI 及工作进程退出。再启动新任务，模型服务只收到对应的新请求。 |
| 取消请求的回执丢失 | Chromium 丢弃已送达服务端的回执，刷新并重试。已确认的事件保留且只追加一次取消终态。 |
| CLI 启动了其他进程 | 测试覆盖独立 Linux 会话和忽略 TERM 的后代进程。回收后进程标识消失，同工作区的另一任务继续运行。 |
| CLI 先退出，后台程序仍持有输出管道 | 工作台读完 CLI 已经写进管道的末尾数据，收回存活的后代并进入正确终态。缺少最后一个换行时，回复和失败诊断也可读取。 |
| 取消与完成同时发生 | 两种先后顺序都得到验证。客户端最终显示 SQLite 已确认的结果，重复请求及后续读取保持一致。 |
| 升级与能力降级 | 以旧版启动的活动任务保留原有输出并可自然结束。主机无法启用子进程回收时，新任务也可执行，界面根据 `canCancel` 决定是否显示按钮。 |

监督进程只处理该任务创建的后代。取消接口将意图写入工作区数据库。负责回收的进程意外退出时，恢复逻辑会报告失败及无法确认停止的原因。Codex 被取消的回合仍可查阅，可以从新任务开始下一段对话。[任务与监督实现](../cloud/tasks.py) · [进程生命周期回归](../tests/test_task_cancel.py) · [浏览器回归](../tests/test_cancel_ui.py)

## InstaBox 实测

Chromium 从本机启动器连到实例上的临时 Git 项目。测试调用真实 Git，并在检查返回前让测试进程等待另一个独立会话中忽略 TERM 的进程。浏览器点击取消，测试刻意丢弃云机已经返回的回执，再刷新并用原任务 ID 重试。

最终记录有 5 条事件，最后状态为“已取消”。云机上两个测试 PID 都已回收，重复取消后事件完全相同，随后启动的项目检查成功。最终源码的一次实测中，从点击到浏览器显示终态用了 1.93 秒，包含控制面往返及浏览器轮询。

本轮在云机运行任务取消、原生 CLI、任务存储、提案和 HTTP 桥接五组回归，34 项通过。2 项需要 Bubblewrap 的系统配置模拟在该实例上跳过。

另在同一实例上运行 Codex 0.160.0。回环模型保持响应流打开时，工作台取消了真实 CLI 进程，并保留已收到的部分回答。普通问答的首轮和追问再次核对了发给模型的工具清单，包含沙箱内的项目命令，两轮均未出现外部 MCP 命名空间。在线模型账户的实测边界见[上一轮认证记录](validation-reviewed-edits.md)。

## 只读问答的外部工具

用 Codex 0.160.0 和 0.172.0-alpha.2 复查普通问答时发现，原来的首轮与续聊命令使用了只读文件沙箱，但模型请求仍列出了主机及用户配置的 MCP 工具。测试通过回环模型服务观察请求，未调用这些模拟工具。

新版本在原项目目录、原用户配置下核对 MCP 服务，按本次调用关闭外部服务、应用扩展、插件和钩子。原生回归分别从新线程和上一版命令生成的真实线程启动。两个 CLI 版本均保留沙箱内的项目命令、自定义模型服务及其认证，测试 MCP 服务未启动。工具清单超时、超限或无法验证时，工作台会在发送文件或提问前显示失败原因。[工具设置](../cloud/codex_tools.py) · [原生 CLI 回归](../tests/test_native_codex.py)

## 短任务的开销

在同一台 Linux 开发机上，对临时 Git 项目分别运行一次预热和 15 次项目检查，从本机提交任务到首次读到终态计时。首次实现为每项任务再启动一个 Python 解释器，中位数约 190 毫秒。现在由单线程监督进程在关闭 SQLite 连接后派生执行进程，以管道在执行结束时唤醒监督进程。

| 版本 | 中位数 | p95 |
| --- | ---: | ---: |
| 上一开发版 `ebce4f7` | 78.33 毫秒 | 141.01 毫秒 |
| 可取消任务 | 90.64 毫秒 | 112.29 毫秒 |

15 个样本的最近秩 p95 恰为这批的最大值。不要用它推断长期尾延迟。计时包含 Git、SQLite 和每 4 毫秒一次的状态查询。浏览器绘制和云机网络往返需单独计时。运行 `python3 experiments/task_lifecycle.py` 可测当前源码，使用 `--checkout` 可对照另一份检出目录。[测量脚本](../experiments/task_lifecycle.py)
