# 0.1 实机验收

2026 年 11 月 25 日，在一台 InstaBox 免费 Linux 实例上部署并运行。实例为 4 vCPU、8 GiB 内存，持久盘 20 GiB。云端实测 Python 3.13.5、Git 2.47.3、Codex CLI 0.160.0、Claude Code 2.1.288。客户端与浏览器自动化运行在独立 Linux 开发机上。

## 正常入口与失效情况

| 场景 | 实际操作 | 结果 |
| --- | --- | --- |
| 打开与编辑项目 | 通过本机 HTTP 入口读取云端 README，写入一行，读 Git 差异，用旧版本再保存，然后恢复初始内容 | 差异包含新增行。旧版本请求返回冲突。恢复后 Git 差异为空。 |
| 任务提交与恢复 | 在真正的云机上以相同请求 ID 两次提交 Git 检查，按游标补读 | 只有一个任务。成功完成，9 个有序事件，最后一个游标再次读取返回空。 |
| 机器暂停与恢复 | 在云机上启动有标识的测试进程并完成一个记录在库的 Git 检查。手动挂起，确认已暂停后恢复。同一请求再次提交 | 进程 PID 及启动标识一致。任务 ID 及全部 9 个事件与暂停前一致。单次观察到达暂停状态约 1.3 秒，从发起恢复至完成额外核验约 2.4 秒。测试进程已结束。 |
| Codex 与 Claude | 两个已存在的真实 CLI 各收到一条只读请求 | 两者均返回模型账户未认证，前端能读取对应失败记录。历史与错误路径已验证。真实模型成功回复、多轮会话和审批尚未验证。 |
| Linux 桌面 | Chromium 通过本机浏览器入口连上实例原有 Xfce 桌面，接管后右键打开菜单，按 Escape 关闭，再交还并重新连接 | noVNC WebSocket 成功。备用 JPEG 逐帧通道也独立验证了鼠标及键盘动作；原生桌面仍在云机上渲染。 |
| 客户端断流 | Linux 本机集成测试在服务端接收提交后拦截响应；刷新时任务还在运行。随后用同一请求 ID 重试并补读 | 任务只启动一次。最终事件逐条一致。浏览器接收新文件版本时，保留正在编辑的中文草稿并提示冲突。 |

全量回归包含 28 项自动化测试，覆盖工作进程、任务存储、回环接口、桌面和 Chromium 操作。浏览器检查了 1440 × 900 和 390 × 844 两种视口。当前实机证据来自 Linux 和 Chromium；Windows、macOS、真实中文输入法候选窗以及大量并发用户仍待单独验收。

## 由测量产生的修改

最初，每次切回一个文件都要等一次远端读取。通过本机桥接连续读取同一个 312 字节 README，15 次暖读往返中位数为 230.4 毫秒，最近秩法 p95 为 297.5 毫秒。计时包括本机 HTTP、InstaBox 控制面、远端 Python 进程、文件读取和完整 JSON 返回。每次 JSON 响应 473 字节。这个结果触发了两次修改。

1. 浏览器现在按工作区保留有限的内存文件缓存。切回已下载的文件，先显示内容，再向云端校验。测试在真实云桥上人为延迟文件请求 1,200 毫秒，7 次切回操作都在校验完成前显示正文。点击到首次检测正文可见的动画帧回调为 5.0–13.4 毫秒，中位数 10.8 毫秒。该数字没有覆盖首次打开或物理显示器延迟。
2. 文件请求增加 `ifRevision`。服务端发现版本未变时，省略正文和图片数据。本机集成测试中，一个 16,800 字节的 UTF-8 文档首次响应体为 17,564 字节，重复校验为 141 字节。更新种子文档后的真机复核中，当前 README 首次响应 470 字节，匹配版本时 134 字节。这里只计应用 JSON 有效载荷。远端仍须读取文件核对摘要。
