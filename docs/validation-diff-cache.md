# 断线后重读 Git 差异

打开“Git 差异”后切回文件，再返回差异时，已读取的各层会先显示上次收到的补丁。后台正在读取时显示“缓存 · 正在校验”。读取失败时显示“缓存未校验”和该层的重试按钮。补丁可以继续翻页和复制。若断线前尚未成功读取某层，界面直接说明读取失败。[工作台使用说明](../README.md)

缓存仅在当前标签页的本次页面会话内有效。整页重载后需要重新读取。工作台可以保存已暂存、未暂存两份补丁，旧工作进程则保存一份合并补丁。空结果和已截断的结果都保留原有含义。只有本次读取确认所有层为空，界面才显示“当前工作区没有 Git 差异”。

## 用云机的实际修改核对恢复

在 InstaBox 的独立 Git 仓库中分别制作一份已暂存改动和一份未暂存改动，再从 Chromium 打开工作台。浏览器拦截工作区 RPC 模拟断线，同时保留云机供独立 Git 进程修改文件。初次读取的已暂存和未暂存补丁分别为 139 和 135 字节。修改后两份补丁的字节数各自保持不变，摘要均发生变化。每次恢复后的工作进程回包均与同一仓库的原生 Git 补丁核对 SHA-256。[云机逐项记录](measurements/diff-cache.json)

| 操作 | 旧版 `76907b8` | 本次改动 |
| --- | --- | --- |
| 两层读完后，断线并从文件返回差异 | 两层正文消失 | 两层均保留，标注“缓存未校验” |
| 在云机更新索引及工作文件，单独重试暂存层 | 暂存层恢复，另一层仍无正文 | 暂存层显示新内容，未暂存层仍能读到带标记的旧内容 |
| 重试未暂存层 | 收到新版未暂存补丁 | 两层分别校验完毕，每次点击只请求对应的一层 |
| 返回正在编辑的 README | 原草稿还在 | 原草稿还在，整个过程没有保存请求，云机文件保持原文 |

本机还在断线时点击了工作台的“刷新工作区”。状态请求失败后，原有两层补丁仍可阅读，恢复连接再刷新可读到新版索引。这次测试保留同一浏览器页面。[刷新记录](measurements/diff-cache.json)

## 缓存何时失效

切换项目时清除上个项目的缓存。在当前工作区访问期间，晚到的身份失效回执也能清除已经离开差异视图的旧内容。访问另一个项目或重新进入同名项目后，先前访问的回执不会清掉新确认的补丁。测试使用真实回环启动器切换两个同名目录。[身份与仓库时序回归](../tests/test_diff_cache_ui.py)

在 InstaBox 的临时仓库中移走 `.git`，让两层读取都得到真实的“没有仓库”回执。用户已切回 README 时放行第一份回执，再断线打开差异，旧补丁已被清除。随后恢复仓库、修改文件并成功读回两份新补丁，再交付第二份较早的回执。断线重开仍可读到修复后的两层。临时仓库在实验结束后清理。[云机实测记录](measurements/diff-cache.json)

当前页收到相同的分层补丁时保留原有 DOM。浏览器回归在第 2 页选中一段文字，再放行后台校验，核对选区、偏移和滚动位置。旧工作进程忽略范围参数时，工作台使用一份合并补丁，并保留其截断提示。升级、降级以及两类回执次序颠倒时分别验证了合并和分层显示。[旧工作进程回归](../tests/test_diff_cache_legacy_ui.py)

## 回归

本机完整回归 150 项全部通过（254.387 秒）。随后为同一视图里的迟到回执补入一个永久回归，在相同产品代码上重跑全部 7 项差异缓存测试（19.691 秒），全部通过。两次合计覆盖 151 个不同用例，其中 62 项使用 Chromium，9 项使用原生模型 CLI，零跳过。[逐项测试结果](measurements/regression-diff-cache.txt)
