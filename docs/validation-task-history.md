# 任务历史翻页与云机升级验收

任务记录每页最多显示 80 项。在“较早”和“较新”之间切换时，工作台继续显示正在阅读的任务、输出和追问草稿。如果该任务属于另一页，选择框会用“当前任务”标出它。第三页起可直接返回“最近记录”。同一标签页刷新后会恢复所选项目的页位置。

Linux 独立源码快照的 87 项回归全部通过，耗时 120.071 秒，零跳过。包括 26 项 Chromium 回归和 9 项原生 CLI 回归。[完整测试清单](measurements/regression-task-history.txt)

## 在 InstaBox 找回升级前的任务

使用上一版 `ac9c08e9` 的云端工作进程，在临时项目中依次提交并完成 163 次独立 Git 检查。旧服务列出最新 80 项。最早任务能按 ID 读到 9 条事件，但新标签页的任务列表里找不到它。

在同一项目和任务库上升级后，用本机 Chromium 经启动器连接 InstaBox，得到以下结果。

| 操作 | 浏览器或云机观察 |
| --- | --- |
| 读取首页，另开一个浏览器会话运行项目检查，然后继续向较早翻页 | 原来的 163 项依次出现在 80、80、3 项的三页中。原任务始终可读，第二个会话提交的新检查成功。 |
| 从第二页翻到第三页时中断一次请求 | 第二页和正在阅读的输出保留。用相同页边界重试，第三页在这次实测中约 420 毫秒后显示。最早任务仍有原来的 9 条事件。 |
| 在第三页选择最早一项，在同一标签页刷新 | 恢复第三页、选中的任务、输出以及输入框中的草稿。 |
| 从第三页返回“最近记录” | 新检查出现在首页。当前阅读的最早任务仍固定在选择框里，整个选择框共有 81 项。 |

另在云机接受一项新检查后暂扣提交回执。用户先翻到第二页，再释放回执。页位置、已选任务和原输出保持一致，从“较新”可返回首页查看新检查的成功结果。

用本机 Chromium 和相同创建时间的 163 条测试记录另行验证了跨页续聊。最早回合保存的追问草稿在刷新后可以发送。延迟返回的旧页不会盖过用户刚刷新的首页。移除分页锚点时，界面会回到最近记录，仍存在的选中任务及草稿可继续使用。旧启动器仅返回一页时，客户端自动清除保存的翻页位置。320 和 360 CSS 像素宽的视口均可操作第三页的全部翻页按钮，无需横向滚动，点击区域至少为 44 × 44 CSS 像素。[浏览器回归](../tests/test_history_ui.py)

在本机 Chromium 里用上一版 HTML 和 JavaScript 连接新版工作进程，也验证了反向兼容。81 条历史记录仍显示最近 80 项，旧页面能打开其中一条、提交新的 Git 检查并刷新。选中任务与全部 9 条事件保持一致。

云机专项回归包含历史分页、任务存储、取消、提案、HTTP 桥接和两种原生 CLI。48 项中 46 项通过，2 项 Codex 系统配置测试因实例缺少 Bubblewrap 跳过。

## 页边界和读取成本

服务端的 `tasks` 请求可携带上一页返回的 `nextBeforeTaskId`，请求字段名为 `beforeTaskId`。同一事务内先用本项目的任务 ID 找到创建时间和 SQLite 行号，再按这两个字段降序读取更早记录。服务端多读一项来决定是否提供下一页。旧客户端仍能从 `tasks` 字段读取最近一页。[分页实现](../cloud/tasks.py) · [端点与边界测试](../tests/test_history.py)

在本地 Linux 上准备了两份固定数据库，每毫秒创建四项任务，包含 Codex、Claude 和项目检查。每组交替运行三种读取方式，各记录 21 个预热后的样本。每次启动独立 Python 工作进程，并核对全部返回 ID 的顺序。下表时间为中位数，包含进程启动、数据库读取和序列化。

| 总记录数 | 上一版首页 | 新版首页 | 新版最后 80 项 | 最后一页响应大小 |
| ---: | ---: | ---: | ---: | ---: |
| 8,000 | 51.69 ms | 50.89 ms | 51.97 ms | 44,545 B |
| 80,000 | 89.30 ms | 91.36 ms | 89.01 ms | 44,545 B |

单独对 80,000 项最后一页的 SELECT 计时，中位数为 0.319 毫秒，p95 为 0.485 毫秒。查询计划显示，同一创建时间内更小的行号，以及更早的创建时间，分别使用已有的 `task_created` 索引。测试还覆盖了数千条任务完全同一时间的情况。运行时开发机还有其他负载，端到端样本不含云机网络往返。[计时与查询计划](measurements/task-history-queries.json)
